## 1 · What this flow is actually for

From Atul's meeting. Every product has a what / why / how:

- **What** we can honestly sell is **not a job**. No company connections yet, so no assured interview. What we *can* guarantee is a **portfolio**.
- **Why**: aspirations → a good life → money → a job → and jobs are won through a portfolio.
- **How**: ZERO gets you there.

The line that reorganises everything: **the vision board is not a goal, it is a mechanic.** Its job is to earn belief that ZERO understands you, so that when it names the roles and the portfolio, you agree instead of arguing.

The old flow asked seven fill-in-the-blank questions. Sanjay: *"उसको लग रहा था तुम fill in the blanks भरवा रहे हो उससे."* Stated preference is weak evidence and gives the user nothing to agree with later. Paired job cards replace it: forced choices are **revealed** preference, and after ten of them "money came second" is something the user remembers doing.

## 2 · Standing rules he has given, in his words

Break these and the work gets rejected regardless of how it looks.

**Layout.** Everything visual and everything selectable lives in the **left panel**. The right side is Zero speaking and asking. (The preference screens still violate this — see §6.)

**Two boards, not one.**
- The **LinkedIn board** is what Zero read off the profile. It is what is on screen during the read-back and the only thing corrected there.
- The **ZERO vision board** is synthesised **after the cards**. It does not exist before them.
Conflating these was a bug he caught twice.

**Withholding.** Zero must not name the user's specific choices until *after* they tap "This is the future I want." Everything before that is offered; everything after is asserted.

**Voice vs keyboard.** Voice is the default. The keyboard appears only where the answer has one correct form — a name, a URL, an email. *"Nobody can tell by voice. It has to be accurate."*

**Permissions.** No screen asking permission to ask permission. The dock shows a mic and a keyboard; **tapping the mic is the intent**, and that is when the browser is asked. Refused → say so once, hand to the keyboard, never loop.

**Copy.** Max two lines on screen, never three. No body text. No em-dashes. Less text, more visual.

**Assets.** Real brand logos from icons0, never hand-drawn. Real product interfaces stay real.

**Ornament.** No decorative edge-to-edge rules — separate with space and enclosure. Green means verified only. No white radial "glare" smears; shine belongs on pills.

**Don't reuse a component that doesn't fit** just because it exists.

**The Figma is a sketch, not a spec.** *"The UI that was there in the Figma was just generated by AI. You don't have to take it literally."* Take the content and the intent; design the surface yourself.

## 3 · Voice

**The opening take is approved** — *"I really like the energy."* Use it as the reference for all future voice work.

- Files: `vo/open-v7.mp3` (master), `vo/raw/open-v7.raw.mp3`, `vo/open-v7.lines.json` (cue points)
- Voice: Navid, `nd1Ukim1avaQS5P3O5dn`, via the **`zero-audio` MCP only**
- Settings that worked: **stability 0.33, similarity 0.85, style 0.50** — low stability + high style is what makes it dynamic rather than even
- **No `<break>` tags.** They make it breathe in the wrong places. Splice real silence with ffmpeg instead — 0.34s between thoughts
- Master: `adelay=260|260, highpass=f=80, equalizer=f=3200:t=q:w=1.4:g=2.2, loudnorm=I=-14:TP=-1.0, alimiter`
- **Shift every cue point by the lead-in** or the text runs ahead of the voice

The calm/slow version was rejected: *"slow and dumb-sounding."* Slow **plus soft** reads as uncertain. Faster + louder + more dynamic together is what reads as conviction.

**Always ask before generating** — except when he explicitly asks for a redo.

## 4 · Traps that have already cost real time

**Assert on every string replace.** Two silent no-ops this session — one left the whole constellation rendering nothing. `s.replace()` that matches nothing returns the string unchanged and reports success.

**Never bound an edit with a lookahead.** A `(?=/\* ---- )` matched a marker 96 KB later and swallowed `</style>` and `<script>`. Destroyed the file; had to restore from the last deploy. Use brace matching with a size assertion.

**`getBoundingClientRect` on a rotated element** returns the axis-aligned box, not the endpoints. I "verified" the connector fix twice against a measurement that was wrong.

**Class collisions.** The file is one global namespace. `.mid` as a bubble modifier inherited the shell column's 84px padding and turned a circle into an ellipse. Prefix everything.

**The preview pane throttles rAF and GSAP.** A cue clock on `requestAnimationFrame` dumps every cue at once. Use `setInterval` + `timeupdate`. To test a GSAP timeline, pump `gsap.ticker.tick()` by hand.

**Measure geometry at draw time, not at entry.** The panel tweens its width for 0.9s; anything measured before that settles is wrong.

**`devPills` must not set `locked`.** Every receiver guards on it, so locking there makes the pill cancel its own click.

## 6 · Pending, in the order it should be built

### 6.1 · The convergence — build this first

This is the piece he is most frustrated about. Current behaviour dumps every company you touched onto the board as another logo: *"That's a receipt, not analysis."*

What it should be: after the cards, the data points **converge into one statement**, and each choice sits inside a **category pool**.

- The selected pool is shown as a bubble — e.g. **AI frontier**, containing the companies chosen from it
- **The neighbouring pools you did not pick are shown too** — that is what gives the selected one meaning
- **Drag a company between pools** to correct Zero, then **Continue**
- Same pattern for location, and for each remaining dimension
- Then the preferences follow

*"It's like a minimum boundary box... you have selected this, non-selected pool... you have a chance to adjust those, change the pool."*

### 6.2 · Preference screens move left and come on-system
Currently on the narration side and traced from the generated Figma sketch. Rebuild in our own language: honeycomb / spectral structures, less text, a Continue-Continue-Continue path that only stops when the user disagrees.

### 6.3 · Loader, blur, highlight system
He has asked for this repeatedly and it should become shared vocabulary rather than per-screen invention:
- **Loader**: reads as Zero understanding more and more, never a spinner. The count that climbs during the read is the right instinct
- **Blur**: depth and focus — what is settled recedes, what is live is sharp
- **Highlight**: the current object states itself without shouting

### 6.4 · The ZERO vision board proper
Built after the cards from everything captured, then offered: *this is you, or not quite*, with adjustment there.

### 6.5 · Smaller centred cards + a progress strip
Choices bank visibly along the bottom as they are made.

### 6.6 · Deck sampling gap — known, unfixed
`rdeck()` picks for dimension **coverage**, so at the default 10 rounds it drops rounds 17 and 18 — the fintech/health round and the Seattle/Vancouver round. **The new categories and cities exist but never appear in a default run.** Fix: prefer variety *within* a dimension, not just coverage across dimensions.

### 6.7 · Remaining product screens
"How ZERO works" embeds the live prototypes (`zero-presentation.vercel.app`, `zero-independent-proto.vercel.app`). Four beats — splash, curriculum, XP→portfolio→job-portal, job portal — show a labelled placeholder because they exist only inside `zero-core-ui`. Capture from the Electron app or build against `design-kit/kit/tokens.css`.

## 7 · Verify before claiming anything

Run in the page console. Do not report a fix as done without one of these.

```js
// every step renders, no errors
for (let i = 0; i < DBG_STEPS.length; i++) { dbgGoto(i); /* wait, check */ }

// round premises hold
RAUDIT                      // must be []

// the read-out cannot lie
rreset(); rdeck().forEach(r => rapply(r, r.n % 2 ? 'a' : 'b')); rreadout()
// a contradictory pattern must DROP a claim, never hedge into a false one

// the board is sane
// 0 overlaps, 0 blocks on the hub, 0 clipped, strokes land on block centres
```

Add `?debug=1` for the audit table.

**And after every scripted edit:** assert the anchor matched, check `<script>` count is 2, check CSS braces balance, and run `node --check` on the last script block.
